# Product Version Changelog

This is the canonical product release history. Change `Versioning/VERSION` and this file first; run `python Maintenance-Tools/Sync-Product-Version.py` to update compatibility version files and release records. Skill versions remain independently governed by their own `VERSION` files.

## [1.11.14] — Trusted Completion Attestations (Repository Update; Not Published)

- Add a fail-closed GitHub Artifact Attestation verifier for task-scoped test receipts. Completion requires a verified signer workflow, matching source commit, task ID, receipt digest, fixed test suite, and zero reported failures.
- Preserve manual close as `CLOSED-UNVERIFIED`; caller-supplied PASS and imported historical results remain unverified unless a genuine signed receipt is supplied.
- Add a Windows CI workflow that runs the full Python and PowerShell suites, signs the test receipt, verifies the signature, and exercises the real Core completion path.
- Add regression coverage for forged or mismatched receipts and the optional PowerShell completion digest.
- Exclude bytecode caches from generated Plugin Skills and keep legacy cache files from invalidating an otherwise byte-verified upgrade.
- Verify the non-Windows safety contract on Ubuntu: guarded mutations fail closed without changing data, while diagnostics and dry-run remain available.
- Verify the signed completion flow end to end in GitHub Actions, including trusted attestation verification and Core completion bound to the tested source commit.
- Platform and TUI versions are synchronized at 1.11.14. Plugin contents did not change; their independent version remains 1.11.13.

## [1.11.13] — Generated Bytecode Exclusion (Repository Update; Not Published)

- Exclude Python bytecode and `__pycache__` from capability inventories and generated Skills/Plugin packages.
- Add regression coverage ensuring only canonical source files are registered and shipped.
- Reject caller-controlled `verified` flags in restored task records and omit them from read projections; preserve the reported value as `reported_result` while exposing the trusted status as UNVERIFIED until a trusted attestation verifier is configured.
- Treat PASS values supplied to the in-memory phase planner as UNVERIFIED and make acceptance records immutable, preventing planner progress or phase closure from trusting caller status.

## [1.11.12] — Windows State Test Portability (Repository Update; Not Published)

- Compare Windows path output according to filesystem case-insensitivity in the Shared Project State Manager routing regression test.
- Synchronize the updated Skill, platform, TUI, Plugin, and capability metadata versions. No packages installed or published.

## [1.11.11] — Verified Task Status And Security Audit (Repository Update; Not Published)

- Prevent caller-reported PASS or manual close from granting verified completion; preserve legacy records and expose unverified state without rewriting history.
- Harden quarantine, transient routing, task-scope and resource boundary checks; clarify that host lifecycle routing remains instruction-only.
- Update affected capability metadata and rebuild local Plugin distributions. No packages installed or published.

## [1.11.10] — Unified Product And Plugin Version

- Move the authoritative product version and release changelog into `Versioning/`.
