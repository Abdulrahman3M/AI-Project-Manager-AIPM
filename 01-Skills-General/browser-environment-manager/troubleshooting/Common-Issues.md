# Diagnostics and Recovery

## Problem and solution examples

Use the evidence in the middle column before choosing a fix. A failed diagnostic is not proof that the browser is unavailable: identify whether the failure came from the browser, the endpoint, or the agent's execution boundary.

| Symptom or error | Likely meaning | Safe response |
|---|---|---|
| `Unable to connect to remote server` or connection refused | The configured port may be wrong, the browser may not have started with CDP, or the listener may have stopped. | Run `Status`; compare the configured port with `edge://version` or `chrome://version`. Preserve the profile while diagnosing. |
| `An attempt was made to access a socket in a way forbidden by its access permissions` when probing `127.0.0.1:9222` | The shell, container, or Windows policy may block local socket access. This alone does not show that CDP is down. | Keep the result as **probe blocked**. Repeat the read-only check only from an authorized host-local context. If that check succeeds, report the sandbox boundary as the cause; if no authorized check is available, report CDP as unverified. |
| `Get-CimInstance`: `Access to a CIM resource was not available to the client` | Process inspection is blocked or unavailable to that execution context. It is separate evidence from the HTTP CDP probe. | Do not guess the listener owner or terminate a process. Use an authorized read-only process query; otherwise report owner verification as unavailable. |
| The sandbox socket error and CIM access error occur together | The diagnostic runner may be isolated from the Windows browser host. In this case, an approved host-local read-only check found the loopback listener and Edge CDP response, showing the earlier failure came from the runner boundary. | Compare results from the same host: listener address and PID, exact browser command line and data directory, and `/json/version`. Do not treat the sandbox result alone as a browser outage. |
| Probe times out | A firewall, network policy, stalled browser, or wrong host boundary may be dropping the request. | Confirm the probe is running on the Windows host that owns the browser. Check the listener and process identity in an authorized context; do not repeatedly launch browsers or reset data. |
| No listener is found on the configured port | The browser may not be running with that CDP port, startup may still be in progress, or configuration may point to the wrong port. | Compare `environment.json` with the browser command line. Start only the named dedicated environment after confirming the port is unused. |
| The port is already in use before launch | Another process owns it; it may be another browser environment. | Identify the owning PID before taking action. Do not kill it blindly. Select an unused port for a new environment or perform a reviewed coordinated port change. |
| Listener address is `0.0.0.0`, a LAN address, or another non-loopback address | Remote debugging is exposed beyond the local machine. | Refuse connection. Stop and review the dedicated launch configuration using the managed environment procedure; never continue with a non-loopback listener. |
| Listener PID does not match a browser process with the exact configured `--user-data-dir` | The port may belong to another environment or an unrelated service. | Refuse connection and inspect the owner and exact command line. Do not infer ownership from the port number or browser name alone. |
| No browser process matches the exact configured data directory | The managed browser is not running, or its launch arguments differ from configuration. | Check the executable and launch arguments. Start the named environment only if the port is free; never attach it to a personal profile. |
| A matching browser process exists, but no listener is present | CDP may not have been enabled, startup may have failed, or the configured port may differ. | Compare `--remote-debugging-port` and `--remote-debugging-address=127.0.0.1` in the parent process command line. Repair the managed shortcut if needed; do not change profile contents. |
| More than one candidate browser parent matches the environment | The environment may have been started more than once or process inspection is ambiguous. | Do not connect until the parent and listener can be identified unambiguously. Avoid launching a duplicate against the same data directory. |
| Command line has a different port or no explicit loopback address | The shortcut or launch configuration is stale or unsafe. | Rebuild the shortcut with `Repair -CreateShortcut` after confirming the saved configuration. Require an explicit loopback address and configured port before connecting. |
| `/json/version` returns another browser signature | The endpoint may belong to Chrome instead of Edge, Edge instead of Chrome, or an unrelated service. | Compare the configured browser type and executable with the returned signature. Refuse the connection on mismatch. |
| `/json/version` responds, but `webSocketDebuggerUrl` uses another host or port | The discovery response does not identify the expected local CDP endpoint. | Refuse connection. Verify the configured port and the exact loopback WebSocket URL; do not pass an unexpected endpoint to an agent tool. |
| HTTP CDP responds, but process or listener ownership cannot be checked | Reachability is proven, but the skill's full process-to-port identity check is not. | Report **HTTP reachable / owner unverified**. Do not label the environment `CDP_VERIFIED` until exact ownership, loopback binding, browser signature, and command-line checks pass. |
| `Unknown environment` or `environment.json` is missing | There is no registered environment with that name. An existing browser profile is not automatically a managed environment. | Do not create a configuration that adopts the existing directory. Use `Create` only for a genuinely new, unused dedicated name, profile directory, and port. |
| `AI-Agent-Browser` metadata is missing after a restart | The owner-authorized dedicated `IB-Edge-Debug` directory may predate the manager record. | Run `Connect -Name AI-Agent-Browser`. It registers a metadata reference only after checking the exact authorized directory and Edge executable; no profile contents are copied or modified. |
| `PROCESS_INSPECTION_UNAVAILABLE` or `LISTENER_INSPECTION_UNAVAILABLE` | The agent runtime cannot read host-local process or TCP state. | Treat this as a permission boundary, not a stopped browser. Run the same non-destructive command from the approved Windows host bridge; do not use a general browser or guess ownership. |
| Configuration schema, name, or browser type is invalid | The file may be incomplete, manually edited, or for a different environment. | Preserve the file and inspect it against the documented schema. Do not guess values or silently rewrite the configuration. |
| Configured data directory is outside `AI-Browser-Profiles\\<Name>` | The configuration points outside the manager's dedicated profile root, possibly at a personal profile. | Refuse to start or connect. Do not change the path to adopt existing data; use a new isolated environment or a reviewed migration. |
| `Create` says the environment or profile directory already exists | Creation is intentionally refusing to overwrite or adopt existing data. | Keep the existing data intact. Inspect the existing environment through its own valid configuration, or choose a new unused name and path. |
| Browser opens the normal or personal profile | An existing browser may have been reused, or launch arguments may have been lost. | Inspect the exact process command line and `Profile path` on the browser version page. Stop automation until the configured dedicated data root is confirmed. |
| Version page shows `Profile 1`, but the folder is named `Profile` | The visible profile label and on-disk subprofile folder are different concepts. | Use the actual `Profile path` from `edge://version` or `chrome://version`; compare it with the configured data directory. Never hardcode a subprofile label. |
| Microsoft sign-in appears in a clean Edge directory | Windows may offer OS-linked sign-in even when browser storage is separate. | Do not accept sync or sign-in unless requested. A dedicated data directory is not an OS sign-in or security sandbox. |
| Configured browser executable no longer exists | The browser may have been moved or uninstalled. | Report the missing executable. Update the configuration only through a reviewed executable migration; do not guess a replacement path. |
| `Start` reports that launch was requested, but no endpoint responds yet | A successful `Start-Process` call only proves that launch was requested. | Wait briefly, then run `Status` or `Connect` for actual listener and CDP verification. Report startup as pending or failed until verified. |
| Desktop shortcut opens the wrong profile or port | The shortcut may have stale arguments or target an older environment. | Run `Repair -CreateShortcut` for the correct saved environment and inspect its target and arguments. Do not edit the profile to compensate. |
| MCP entry such as `edge-ai` exists, but the agent has no browser tools | MCP registration and tool availability in the current agent session are separate. | Check tool exposure in the current session and whether the agent runs locally or in the cloud. Refresh or reconnect the supported agent session, then verify again. |
| Browser works locally, but a cloud agent cannot reach `127.0.0.1` | Loopback in the cloud agent refers to its own runtime, not the user's Windows host. | Use a supported, explicitly configured remote bridge or local agent runtime. Never assume identical loopback namespaces or silently switch to a personal browser. |
| `Connect -NavigateTest` verifies CDP, but no test tab is created | The endpoint may allow discovery but reject the new-target request, or the navigation request may have failed. | Report CDP discovery and navigation separately. Inspect the returned error and retry only against the verified dedicated endpoint. |
| The new target reports a URL other than `https://example.com/` | The browser did not confirm the requested test destination. | Mark navigation unverified and inspect the resulting URL. Do not claim navigation succeeded based only on the tab-creation response. |
| CDP is healthy, but no screenshot is available | HTTP CDP health checks do not prove that the agent can inspect or capture a page. | Use an available compatible agent browser tool for visual verification. If none is exposed, report `CDP_VERIFIED / AGENT_TOOL_UNAVAILABLE / SCREENSHOT_NOT_RUN`. |
| Firefox is requested | Firefox uses WebDriver BiDi or Marionette, not Chromium CDP. | Do not send Firefox to this CDP workflow. Use a separately tested adapter when one is available. |
| Chrome refuses CDP with its default profile | Current Chrome releases may reject remote debugging against the default data directory. | Use a new dedicated non-default `--user-data-dir`. Never enable debugging on the user's personal Chrome profile. |
| A reset is requested to fix a connection problem | Reset changes profile state and is not a generic connectivity repair. | Require explicit consent, confirm the named environment is stopped, and archive the profile first with `-ConfirmReset`. Keep the archive until the user verifies it. |
| Browser update or profile preference change is expected from `Repair` | `Repair` checks and can rebuild a shortcut; it does not upgrade the browser or reset/change the profile. | Treat executable upgrades and profile changes as separate reviewed tasks. Report the distinction instead of implying `Repair` performed them. |

## Diagnostic sequence

1. Read the per-environment `environment.json`; never guess the environment name or profile directory.
2. Run `Status` and verify the exact `--user-data-dir` process, loopback listener, and listener-owning PID.
3. Run `Connect` to check `/json/version`, the browser signature, and the loopback `webSocketDebuggerUrl`.
4. If a probe is blocked by sandbox or host policy, record the exact error and execution boundary. Repeat only through an authorized read-only host-local diagnostic; otherwise leave that check unverified.
5. If a compatible agent browser tool is available, inspect the real active profile path. Use `-NavigateTest` for navigation and the agent tool for screenshots; these are separate checks.
6. Report each level independently: `CONFIGURED`, `BROWSER_RUNNING`, `CDP_VERIFIED`, `ACTIVE_PROFILE_VERIFIED`, `NAVIGATION_VERIFIED`, `SCREENSHOT_VERIFIED`, and `NOT_TESTED`.

Never use broad process termination, delete browser data, or treat a live port by itself as proof of environment ownership.
