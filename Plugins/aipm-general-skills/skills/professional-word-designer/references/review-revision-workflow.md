# Review, Revision and Response Workflow

Preserve the original and create a revision workspace.

## Reviewer-response matrix

For each comment record: reviewer/comment ID, verbatim or safely summarized request, interpretation, action, affected location, response, status and verification.

Native Word Track Changes/comments are claimed only if the actual OOXML/native feature is created and checked. A textual diff is not Track Changes.

## Requirements and examples

- REQ-RV-01 — original file is preserved.
- REQ-RV-02 — every reviewer comment has a tracked disposition.
- REQ-RV-03 — claimed native comments/tracking are structurally verified.
- REQ-RV-04 — rejected reviewer requests receive a reasoned response rather than silent omission.
