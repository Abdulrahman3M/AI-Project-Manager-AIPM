# Research Synthesis And Attribution

This AIPM-authored Skill compares public materials as research inputs. It does not copy their instructions, datasets, generated assets, source code, or proprietary/paid content.

| Source | Valuable practice adopted | Limitation avoided |
| --- | --- | --- |
| [Impeccable](https://github.com/pbakaus/impeccable) | Deliberate visual inspection and anti-generic critique | Aesthetic pressure is converted into explicit, product-specific decisions rather than a universal look |
| [Anthropic Frontend Design](https://github.com/anthropics/skills/tree/main/skills/frontend-design) | Subject-led direction, typography, restraint, copy and motion discipline | Does not prescribe a single default visual idiom or replace product requirements |
| [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) | Searchable decision support, stack awareness, resilient text and pre-delivery checks | Does not vendor a huge style database or require a CLI, package, or external dataset |
| [Taste Skill v2](https://github.com/Leonxlnx/taste-skill) | Direction selection, browser evidence, and substantive content over ornament removal | Does not require a particular Node/browser version, external assets, or a fixed house style |
| [Emil Design Engineering](https://github.com/emilkowalski/skills) | Invisible interaction details, animation purpose, interruption, and feel | Does not mandate a personality, table format, or animation-first workflow |
| [Agent Website Design Skills](https://github.com/divyanshu-iitian/agent-website-design-skills) | Narrow routing among direction, systems, landing pages, and verification | Keeps the package compact and framework-neutral rather than fragmenting ordinary work |
| [Design System Ops Accessibility](https://github.com/murphytrueman/design-system-ops) | Component-level keyboard, screen-reader, contrast, focus, and ARIA review | Does not overclaim legal compliance from a static audit |
| [Web Design Skill](https://github.com/max0821/web-design-skill) | Final re-comparison after the latest visual change | Does not require an approval loop for every ordinary UI edit |

## Resulting Principles

1. Direction must emerge from the actual product, audience, and job.
2. Quality depends on both aesthetics and behavioral correctness.
3. A design system should be small, role-based, local-stack compatible, and testable.
4. Responsive, localization, accessibility, and reduced-motion behavior are normal product states.
5. Rendered, current evidence closes a visual task; older screenshots and source inspection do not.
