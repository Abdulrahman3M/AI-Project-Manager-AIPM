# Accessibility, cross-format publishing and human review

- Assign actual heading levels H1/H2/H3, not manually bolded text. Keep reading order logical in mixed-script paragraphs; test copy-paste and text-to-speech order for Arabic where tooling exists.
- Provide useful alt text for content-bearing images; decorative strokes should be explicitly decorative. For a full causal diagram include adjacent equivalent prose or structured accessible table.
- Every table needs semantic header rows, units, source if factual, a short intro, and plain-language summary for complex cases. Avoid nested layout tables when a simple paragraph suffices.
- Test chart palette in grayscale and under color-blindness assumptions; encode differences with direct labels or line/marker shapes in addition to color.
- Cross-format export uses content JSON/source ledger as canonical meaning. Word remains an independently proofed deliverable; an HTML companion is not equivalent to Word and a static DOCX is not a JS app.
- Native proofreading required for formal publication if a qualified person is available; if unavailable perform the strongest possible language check and state it as such. Never promise perfect translation or guaranteed absence of AI-detection signals.
- Optional accessibility references: Microsoft Word accessibility checker and applicable WCAG principles, without claiming automatic certification.
