# Screenshot To Code Research And Synthesis

**Review date:** 2026-10-26. **Owner:** Abdulrahman ElBatrah. **Deliverable:** original AIPM `screenshot-to-code` Skill, not an implementation handoff.

## Method And Evidence Limits

Search covered screenshot-to-code, image-to-code, image-to-website, design-to-code, web cloning, design extraction and visual QA. GitHub topic pages and web search were discovery aids; the review used primary repository README files, available `SKILL.md` files and selected source helpers. `Screenshot-To-Code-Sources.json` records the inspected paths and Git blob SHAs. Blob SHAs pin file content, not repository commit dates. A missing guessed path was retried when README documentation identified the real path.

31 repositories were attempted; 29 supplied readable primary evidence. This is a broad bounded landscape, not an exhaustive enumeration of GitHub. Forks were not multiplied to inflate coverage. The Mrxyy/screenshot-to-page README and microsoft/AI-Lab README requests returned 404 and are discovery-only exclusions, not audited implementations. No downloaded third-party script was executed, installed or redistributed. Described strengths come from inspected instructions/source; limitations below are either explicit upstream constraints or engineering assessments of fit. They are not comparative runtime benchmarks or claims that an unmentioned feature does not exist.

## Synthesis Decisions

1. **Evidence before precision:** store observed/measured/inferred/unknown distinctions, hashes, CSS-vs-raster geometry and unknown font identity.
2. **Direct execution:** preserve the existing app, routes and business behavior; do not stop at a prompt or handoff.
3. **Visual authority:** use the original image, supplied fonts and assets; no mandatory re-generation, random stock imagery or automatic redesign.
4. **Semantic reconstruction:** real text, controls and layout relationships; a screenshot bitmap is not an accepted implementation.
5. **Verification without false certainty:** equal-sized captures, regional metrics, raw/masked results, fresh evidence and independent behavior/responsive/accessibility gates.
6. **Controlled cost:** one agent, optional helper tools, progressive references, bounded repair batches and honest residuals.
7. **Multilingual quality:** explicit Arabic/RTL, mixed-direction IDs, diacritics, actual glyph coverage and browser inspection.

## Verification Scope

Numeric helper tests and a controlled local browser fixture are appropriate to validate diagnostics and evidence plumbing. They do not prove an agent can reconstruct every unseen screenshot or that the synthesis outperforms all reviewed tools. Behavioral evaluation scenarios are shipped explicitly as NOT RUN until executed on held-out tasks. See the task verification record for actual command results and limitations.
