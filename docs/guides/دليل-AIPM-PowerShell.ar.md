# دليل تشغيل AIPM باستخدام PowerShell

يشرح هذا الدليل تشغيل واجهة AIPM الطرفية (TUI)، وهي أداة مبنية على PowerShell لإدارة تسجيل المشاريع وسياق المهام والأدلة والتسليم بين الوكلاء. ويركز على الاستخدام اليومي وحدود الأداة ونقاط قوتها.

## ما الذي تفعله AIPM؟

تحتفظ AIPM بسجل لمسارات المشاريع، وتضع بياناتها المُدارة داخل `Shared-Project-State-Manager/` في كل مشروع. تستدعي الواجهة المحرك الأساسي لتنفيذ العمليات المسموح بها والتحقق منها. لا تكتب AIPM الشيفرة المصدرية للمشروع، ولا تعدّل ملفاتها، ولا تشغّل اختبارات المشروع. ينفذ المطور أو وكيل الذكاء الاصطناعي هذه الأعمال مباشرة في مجلد المشروع ووفق صلاحيات النظام المضيف.

## المتطلبات والتشغيل

- Windows PowerShell 5.1 أو PowerShell 7.x، ويُفضّل PowerShell 7.
- Python 3.10 أو أحدث، متاح باسم `python` أو `python3`.
- Git متاح عبر `PATH` عند تسجيل مشروع أو استخدام تدفقات Git.
- نافذة طرفية تفاعلية للتنقل بلوحة المفاتيح.

من جذر المستودع، شغّل `AIPM.bat` على Windows أو `./AIPM.sh` على Linux وmacOS مع تثبيت `pwsh`. ويمكن استخدام الأوامر التالية مباشرة:

```powershell
Set-Location 'C:\Path\To\AI-Project-Manager-AIPM'
./TUI/AI-Project-Manager/Start-AIPM.ps1
./TUI/AI-Project-Manager/Start-AIPM.ps1 -RegistryPath 'D:\AIPM Data\registry.json'
./TUI/AI-Project-Manager/Start-AIPM.ps1 -Version
```

عند التشغيل الأول، اختر السجل الافتراضي أو اربط سجلًا موجودًا أو حدد مسارًا جديدًا. يحتوي السجل على معرفات المشاريع وأسمائها ومساراتها فقط؛ ولا ينسخ مجلدات المشاريع. يتحقق AIPM من السجل الموجود دون استبدال محتواه.

## التنقل

- **Up/Down** لتحريك التحديد، و**Enter** للفتح أو التأكيد، و**Esc** للعودة.
- اكتب رقم الخيار الظاهر لتحديده مباشرة.
- اضغط **/** لتصفية الإجراءات، و**?** أو **F1** لعرض المساعدة.
- يطلب **Q** الخروج، وتطلب لوحة التحكم تأكيدًا.
- من الإعدادات يمكنك اختيار لوحة المهام أو لوحة الأوامر أو وحدة المساعد. وحدة المساعد عرض أدلة محلي للقراءة فقط وليست جلسة ذكاء اصطناعي.

## تسجيل مشروع

من **Registry Management** اختر **Register Project**، ثم حدد جذر المشروع الحالي وأدخل الاسم المعروض. يتحقق النظام من وجود Git في جذر المشروع نفسه؛ وجود مستودع أب في مجلد أعلى لا يكفي. إذا لم يكن Git مفعّلًا، يطلب AIPM الإذن قبل تهيئته. بعد ذلك ينشئ `Shared-Project-State-Manager/` ويضع FIRG في `Shared-Project-State-Manager/FIRG/` ويسجل المشروع.

يوضح ملف `AGENT.md` داخل مجلد الحالة وظائف المجلدات وقواعد حفظ كاش Python داخل `Temporary-Files/Cache/` ومجلدات الاختبارات المؤقتة داخل `Temporary-Files/Test-Workspace/`. ملفات التعليمات التي تحتوي بيانات وصفية أو ترجمات أو قواعد FIRG متعارضة تتطلب مراجعة بدل استبدالها آليًا.

## تحديث مشروع مسجل

من **Projects** اختر المشروع ثم **Update Project**. يمكن للأداة تهيئة Git بعد موافقتك، ونقل FIRG المُدار من جذر المشروع إلى مجلد الحالة، أو تثبيته داخله إذا لم يكن موجودًا، وترحيل مجلدات الكاش والاختبارات والتشغيل القديمة. تحافظ الأداة على المحتويات وتتوقف إذا تعارض المجلد الهدف أو وجدت ملفات غير مُدارة أو تعديلات تحتاج مراجعة. نجاح النقل لا يعني اختبار كل إعداد محتمل للمشروع.

## المهام والأدلة والتسليم

افتح **Tasks** وحدد المشروع، ثم أنشئ مهمة أو افتح مهمة موجودة. المهمة سجل للنطاق والتقدم وليست نسخة عمل من المشروع. استخدم خياراتها لتسجيل النطاق والخطة ونقاط التحقق والعوائق وأدلة التحقق والتقارير ومعلومات التسليم. يمكن إرفاق ملفات داعمة ضمن تصنيفات المهمة؛ الإرفاق ينسخ الملف المختار إلى بيانات AIPM ولا يغير الأصل. تبقى تعديلات الشيفرة والاختبارات في شجرة المشروع الأصلية.

استخدم **Tests & Evidence** لمراجعة نتائج الفحوص التي أبلغ عنها الوكيل. الأدلة التي لم تُقدّم تبقى مجهولة أو غير متحقق منها؛ حالة المهمة أو التقرير لا يثبتان وحدهما أن الاختبارات نُفذت. يجهز **Agents & Handoffs** سياق المهمة للوكيل التالي، وعلى الوكيل إعادة قراءة ملفات المشروع والتحقق من نقطة التوقف قبل المتابعة.

## Git وتقارير FIRG

تاريخ Git جزء من المشروع. قد تطلب AIPM توثيق FIRG بعد commit يُنفذ من واجهة المهام. ويمكن تثبيت hook محلي تفاعلي بعد commit ليطلب التوثيق بعد عمليات commit الأخرى عندما لا يتعارض مع hooks الموجودة. يمكن تجاوز hooks، كما لا تستطيع البرامج غير التفاعلية الإجابة عن المطالبة. استخدم FIRG `commit-status` لمعرفة commits التي لا ترتبط بتقرير. يوثق التقرير commit وملخص التغيير والتحليل والسبب الجذري عند وجود مشكلة والحل ونتيجة التحقق، لكنه لا يثبت صحة التغيير بمفرده.

## الاستعادة والإعدادات

يعرض **Upgrade Shared State** ترقية مدعومة للمخطط، ثم يطلب التأكيد قبل إنشاء نسخة احتياطية وتسجيل الحدث. يجب معالجة المعاملات المعلقة وتعارضات التطبيع عبر أدوات استعادة الحالة أولًا. تتيح إدارة السجل الربط والتبديل والنسخ الاحتياطي والاستعادة والتسجيل وإلغاء التسجيل. إلغاء التسجيل يزيل مرجع السجل ولا يحذف ملفات المشروع. تحفظ إعدادات الواجهة ومسار السجل في إعدادات المستخدم، منفصلة عن حالة كل مشروع.

## نقاط القوة والحدود

**نقاط القوة:** سجل موحد لمسارات المشاريع، وملاحظات وأدلة خاصة بكل مهمة، وتجهيز صريح لـGit وFIRG، وترحيل محروس للحالة، ونسخ احتياطية للإصلاحات المدعومة، وسياق قابل للتسليم بين الوكلاء، ودعم PowerShell 5.1 و7.

**الحدود:** AIPM ليست محرر شيفرة أو بيئة تشغيل للوكيل؛ ولا تشغّل اختبارات المشروع أو تضمن صحة الأدلة المبلّغ عنها. يمكن تجاوز Git hooks، ويجب أن تكون مسارات السجل صالحة على الجهاز الحالي. تختلف الألوان والرموز بحسب الطرفية، واختبارات العرض الآلية لا تثبت جودة المظهر أو خلو كل طرفية من الوميض. تحمي ضوابط المسارات عمليات AIPM نفسها، لكنها لا تمنع برنامجًا آخر يملك صلاحية مباشرة من تعديل الملفات.
