# دليل المبتدئين إلى مدير المشاريع بالذكاء الاصطناعي

مرحبًا بك في **AI Project Manager (AIPM)**. يشرح هذا الدليل، خطوة بخطوة، كيفية الحصول على المشروع وتشغيله وفهم شاشاته واستخدام قدراته المعتمدة بأمان، حتى لو كانت هذه أول مرة تتعامل فيها مع المشروع.

> **مهم:** ينظم AIPM سياق المهمة وملفاتها المساعدة داخل `Shared-Project-State-Manager/`، ولا يحرر ملفات المشروع الفعلية ولا يشغّل اختباراتها ولا يوافق على تغييرات الوكيل. يعمل AI Agent على الملفات الأصلية داخل المشروع وفق صلاحيات وقواعد المشروع والمضيف. تتيح TUI إنشاء سجلات المهام وإدارتها مع إبقاء ملفات المصدر دون تغيير. حزمة Agent Bridge عينة وليست وكيلا مثبتا ولا تمنح وصولا تلقائيا للملفات.

## 1. ما وظيفة AIPM؟

ينظّم AIPM معلومات المشروع بطريقة واضحة تستند إلى الحالة والأدلة، ليساعد الأشخاص ووكلاء الذكاء الاصطناعي عند العمل المشترك:

| الجزء | معناه ببساطة |
| --- | --- |
| Core Engine | يقرأ ويتحقق من حالة المشروع، ويوفر أوامر المهام والتسليم. |
| Capability Library | يحتفظ بفهرس معتمد للمهارات والمطالبات مع الإصدار والمصدر وسجل السلامة. |
| PowerShell TUI | لوحة طرفية تعرض بيانات المشروع وتدير السجل والمهام بخطوات موجهة. |
| Project Agent Bridge | يشرح طريقة تكامل وكيل متوافق؛ أما الحزمة الموجودة فهي عيّنة محلية غير مثبتة وغير نشطة. |
| Host Adapters | يصف التكاملات والصلاحيات المسموحة ويرفض افتراضيًا العمليات غير المدعومة. |

## 2. جهّز جهازك

يعمل المشروع على Windows مع **Windows PowerShell 5.1** أو **PowerShell 7.x**، ويظهر أمر الإصدار الأخير باسم `pwsh`. ثبّت أيضًا **Python 3.10** أو أحدث، وتأكد من أن أمر `python` يعمل في نافذة طرفية جديدة. التنقل بلوحة المفاتيح يحتاج نافذة تفاعلية حقيقية مثل Windows Terminal؛ أما الأنابيب والمخرجات المعاد توجيهها فليست جلسة تفاعلية.

تحقق من الأدوات:

```powershell
python --version
pwsh --version
```

إذا لم يكن PowerShell 7 مثبتًا، يمكنك استخدام Windows PowerShell 5.1.

## 3. احصل على المشروع

إذا كان لديك حق الوصول إلى مستودع GitHub الخاص بمالك المشروع، استنسخه هكذا:

```powershell
git clone https://github.com/Abdulrahman3M/AI-Project-Manager-AIPM.git
Set-Location AI-Project-Manager-AIPM
```

وإذا استلمت ملف ZIP، ففك ضغطه في مجلد تملكه وافتح PowerShell داخله. مجلد المشروع الرئيسي هو المجلد الذي يحتوي على `README.md` و`VERSION` والمجلدين `Core-Engine` و`TUI`.

قبل استخدام ملفات المشروع أو إعادة توزيعها، اقرأ [رخصة الاستخدام الشخصي الخاصة بـAI Project Manager](../../LICENSE).

## 5. افتح لوحة التحكم الطرفية

من المجلد الرئيسي للمشروع شغّل:

```powershell
TUI\AI-Project-Manager\AIPM.bat
```

يختار المشغّل إصدار PowerShell المتاح والمدعوم. لتشغيل الواجهة مباشرةً باستخدام PowerShell 7:

```powershell
pwsh -NoProfile -File TUI\AI-Project-Manager\Start-AIPM.ps1
```

ولتحديد Windows PowerShell 5.1 صراحةً:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File TUI\AI-Project-Manager\Start-AIPM.ps1
```

عند التشغيل لأول مرة، تتيح الواجهة استخدام السجل الافتراضي أو ربط ملف سجل موجود أو اختيار موقع آخر. تعرض اللوحة أقسام المشاريع والمهام والمراحل وأدلة الاختبار وعمليات التسليم والمهارات والمطالبات والإعدادات. تظهر أسماء المشاريع المسجلة داخل قسم **Projects**، وليس كخيارات مستقلة في الصفحة الرئيسية. وتتيح شاشة **Registry Management** ربط سجل موجود وتسجيل المشاريع وإلغاء تسجيلها وتغيير موقع السجل وإنشاء نسخة احتياطية أو استعادتها. يبدأ قسم **Tasks** بتحديث السجل ثم يطلب منك اختيار مشروع مسجل قبل إنشاء مهامه أو إدارتها. تعدّل عمليات المهام حالة AIPM فقط، ولا تمس ملفات المصدر.

## 6. اختر مكان حفظ قائمة المشاريع

السجل ملف صغير يحفظ لكل مشروع **معرّفًا واسمًا ومسار مجلد فقط**. لا يحتوي ملفاتك ولا سجل المهام والتغييرات.

الموقع الافتراضي في Windows هو:

```text
%LOCALAPPDATA%\AI-Project-Manager\registry.json
```

بالنسبة إلى حسابك، تكون قيمة `%LOCALAPPDATA%` غالبًا مثل:

```text
C:\Users\اسم-حسابك\AppData\Local
```

وبالتالي يكون المسار الكامل المعتاد:

```text
C:\Users\اسم-حسابك\AppData\Local\AI-Project-Manager\registry.json
```

هذا مجلد بيانات خاص بحساب Windows، وليس نسخة ثانية من AIPM ولا مجلدًا داخل مشروعك. إذا كان لديك ملف سجل موجود من جهاز آخر، اختر **Use An Existing Registry File** عند الإعداد الأول، ثم أدخل المسار الكامل لملف JSON الذي نسخته إلى هذا الجهاز. ويمكنك لاحقًا اختيار **Registry Management → Connect Existing Registry File**. تتحقق AIPM من الملف دون تغيير محتواه وتحفظ اختيارك في `%APPDATA%\AIPM\settings.json`. تذكّر أن السجل يحفظ مسارات المشاريع فقط، ولا ينسخ مجلدات المشاريع أو حالة المهام؛ يجب أن تكون مجلدات المشاريع موجودة على هذا الجهاز في المسارات المسجلة، وإلا ستظهر حالتها غير متحقق منها. لإنشاء سجل جديد بموقع آخر، اكتب المسار الكامل لأي ملف ينتهي بـ`.json` خارج تثبيت AIPM؛ كتابة مسار المجلد وحده غير كافية. وإذا شغّلت AIPM مع الخيار `-RegistryPath` فقد اخترت المسار صراحةً.

أما بيانات العمل والحالة، فتحفظ داخل كل مشروع في مجلده الخاص `Shared-Project-State-Manager/`. بهذه الطريقة يبقى السجل المركزي صغيرًا، وتبقى حالة كل مشروع معه.

للاطلاع على أمثلة لخطط المهام والتسليم بين الوكلاء وسياسة التعامل مع الملفات، راجع [قالب وأمثلة حالة المشروع](../../Templates/Shared-Project-State-Manager-Example/README.md). هذه بيانات تعليمية وهمية وليست مشروعًا حيًا؛ لا تسجّل مجلد القالب ولا تنسخه بالكامل إلى مشروعك. سجّل مشروعك أولًا لكي تنشئ النواة حالة جديدة بمعرّف وبيانات خاصة به، ثم استخدم المستندات النموذجية الفردية كمرجع. لا تستبدل ملفات Manifest التي أنشأتها النواة بملفات القالب.

## 7. تنقّل بين الشاشات

- اضغط **السهم لأعلى** أو **السهم لأسفل** لتغيير الخيار المحدد.
- اضغط **Enter** لفتح الخيار.
- اكتب رقم الخيار الظاهر لاختياره مباشرةً.
- اضغط **/** للبحث أو التصفية حيث تتوفر.
- اضغط **?** أو **F1** لعرض المساعدة.
- اضغط **Esc** للعودة إلى الشاشة السابقة. وعند الوصول إلى الشاشة الرئيسية، يعرض **Esc** تأكيد الخروج بدلًا من إغلاق PowerShell مباشرة؛ اختر **Stay Here** للبقاء داخل AIPM.
- اضغط **Q** للخروج ثم أكّد الخروج عند ظهور الطلب.

يشير سهم ملون ونص أوضح إلى الخيار المحدد. لا يتم تظليل الشرح أسفل الخيارات. إذا لم تظهر الرموز بصورة صحيحة، استخدم إعداد ASCII الموضح في [دليل واجهة الطرفية](../../TUI/AI-Project-Manager/README.md).

## 8. سجّل مشروعًا وأدر السجل بأمان

من لوحة التحكم اختر **Registry Management**. لتسجيل مشروع:

1. اختر **Register A Project**.
2. أدخل المسار الكامل لمجلد مشروع موجود. لا تختر مجلد AIPM نفسه ولا مجلدًا أعلى منه يحتوي AIPM؛ فالنواة تمنع المسارات المتداخلة.
3. أدخل اسم العرض أو اقبل الاسم المقترح.
4. اقرأ رسالة التأكيد: ستوضح أن AIPM سينشئ مجلد `Shared-Project-State-Manager/` داخل المشروع ولن يغيّر ملفات المصدر.
5. اختر **Create State And Register** فقط إذا كنت تريد إنشاء مجلد الحالة وإضافة المشروع إلى السجل.

بعد ذلك يسجل AIPM معرّف المشروع واسمه ومساره. لا يتغير كودك أو مستنداتك أو ملفات Git الموجودة؛ وتبقى سجلات المهام والاستمرارية التي ينشئها AIPM داخل مجلد الحالة. بعد نجاح التسجيل ستظهر رسالة تطلب منك العودة إلى الصفحة الرئيسية واختيار **Refresh**. بعد التحديث افتح **Projects**؛ ستجد المشروع داخل هذا القسم، وليس كخيار منفصل في الصفحة الرئيسية.

أدوات أخرى في شاشة السجل:

- **View Registered Projects** تعرض اسم كل مشروع ومعرّفه ومجلده.
- **Unregister A Project** تزيل مرجع المشروع من السجل المحدد فقط. لا تحذف المشروع أو مجلد الحالة.
- **Back Up Registry** تنشئ ملف JSON جديدًا ومعه ملف تحقق `.sha256`، ولا تستبدل ملفًا موجودًا.
- **Restore Registry Backup** تتحقق من البصمة عند وجودها وتحفظ نسخة أمان من السجل الحالي قبل الاستعادة.
- **Change Registry Location** تختار سجلًا آخر أو تنشئه. لا تنقل بيانات السجل السابق ولا تحذفه؛ أنشئ نسخة احتياطية أولًا إن أردت الاحتفاظ ببياناته.
- **Connect Existing Registry File** تتحقق من ملف سجل `.json` موجود وتختاره دون استبدال محتواه. استخدمه عند نقل إعداد AIPM إلى جهاز جديد، وتأكد من وجود مجلدات المشاريع على المسارات المحفوظة في السجل.

لا تضع السجل أو النسخة الاحتياطية داخل تثبيت AIPM. النواة تمنع المسارات التي تتداخل معه.

## 9. اقرأ معلومات Core من PowerShell

شغّل الأوامر التالية من المجلد الرئيسي. تعرض النتائج بتنسيق JSON ليسهل قراءتها:

```powershell
python Core-Engine\aipm.py health
python Core-Engine\aipm.py catalog
python Core-Engine\aipm.py host-capabilities
python Core-Engine\aipm.py dashboard
```

يعرض `health` أن أداة Core بدأت. ويسرد `catalog` بيانات الفهرس، لكنه لا يثبت أن مضيفًا ثبّت مهارة أو شغّلها. ويعرض `host-capabilities` الصلاحيات المعلنة للمحولات. أما `dashboard` فيقرأ سجل المشاريع والحالة المضبوطين.

لقراءة سجل مشاريع محدد، أضف مساره. استبدل المسار ورقم المشروع في الأمثلة بالقيم التي زوّدك بها المسؤول:

```powershell
python Core-Engine\aipm.py list --registry "C:\path\to\project-registry.json"
python Core-Engine\aipm.py inspect --registry "C:\path\to\project-registry.json" --project-id "YOUR_PROJECT_ID"
python Core-Engine\aipm.py state-read --registry "C:\path\to\project-registry.json" --project-id "YOUR_PROJECT_ID"
```

توجد كذلك أوامر صريحة لإدارة السجل من سطر الأوامر. استخدم مسارات ومعرّفات حقيقية ومصرحًا بها. التسجيل ينشئ مجلد حالة خاصًا بـAIPM داخل المشروع، أما إلغاء التسجيل فيزيل المرجع فقط.

```powershell
python Core-Engine\aipm.py registry-init --registry "$env:LOCALAPPDATA\AI-Project-Manager\registry.json"
python Core-Engine\aipm.py registry-register --registry "$env:LOCALAPPDATA\AI-Project-Manager\registry.json" --project-root "D:\Work\My-Project" --project-id "my-project" --alias "My Project"
python Core-Engine\aipm.py registry-backup --registry "$env:LOCALAPPDATA\AI-Project-Manager\registry.json" --destination "$env:USERPROFILE\Documents\registry-backup.json"
python Core-Engine\aipm.py registry-unregister --registry "$env:LOCALAPPDATA\AI-Project-Manager\registry.json" --project-id "my-project"
python Core-Engine\aipm.py registry-restore --registry "$env:LOCALAPPDATA\AI-Project-Manager\registry.json" --source "$env:USERPROFILE\Documents\registry-backup.json"
```

لإدارة سجل المشاريع، يفضّل اختيار الأوامر من TUI وقراءة رسائل التأكيد. لا ترفع سجلًا شخصيًا أو نسخة احتياطية إلى GitHub أو ملف التوزيع؛ فقد تكشف مسارات مجلدات مشاريعك الخاصة.

## 10. أنشئ مهمة وسلّمها إلى وكيل آخر

لكل مشروع مسجّل سجل مستقل ومجلد ملفات مساعدة مستقل في `Shared-Project-State-Manager/Tasks/<Task-ID>/`. لإدارة المهام بالطريقة العادية لا تحتاج إلى كتابة أوامر:

1. من الصفحة الرئيسية اختر **Tasks**.
2. يحدّث AIPM السجل المختار. إذا كان فارغًا، اختر **Register A Project First** وأكمل تسجيل المشروع، ثم عد إلى قسم **Tasks**.
3. اختر المشروع المسجل الذي تتبعه هذه الأعمال. مجلد المهام ليس مشروعًا مستقلًا إلا إذا كان مساحة مشروع مستقلة فعلًا.
4. اختر **Create New Task** لإنشاء سجل مهمة جديد، أو **Add Existing Work Folder** لتسجيل مجلد عمل موجود مسبقًا داخل المشروع المختار. يبقي AIPM الملفات الأصلية في مكانها، ويسجل جردًا للملفات ضمن مراجع المهمة ليسهّل استئناف العمل.
5. اختر **Open Existing Task** ثم اختر المهمة. ستظهر قائمة **Manage Task** مباشرةً، ويظهر فيها وضع المهمة ومعرّفها. استخدم **Mark Task Complete** لإغلاقها مع ملاحظة إنجاز، و**Reopen Task** عند الحاجة إلى عمل لاحق. ينشئ **Archive Completed Task** ملف ZIP وبصمة SHA-256 داخل `Shared-Project-State-Manager/Archive` مع إبقاء سجل المهمة متاحًا. يسجل AIPM الأدلة ولا يشغّل اختبارات المشروع.
6. لإرفاق ملف تقرير أو خطة، اختر **Attach Plan, Report Or Supporting File** ثم اختر **Reports** أو **Instructions And Plans**، وأدخل المسار الكامل للملف الموجود، وحدد اسم الملف داخل المهمة، ثم وافق على النسخ. ينسخ AIPM الملف المختار إلى مجلد ملفات الدعم الخاص بالمهمة، ويُبقي الملف الأصلي في مكانه. الحد الأقصى 16 MiB، ولا يستبدل ملفًا مرفقًا موجودًا بصمت. استخدم **View Attached Task Files** لمراجعة الملفات. إذا كانت القائمة طويلة، استخدم السهمين لأعلى/لأسفل أو PageUp/PageDown للتنقل بين الصفحات. من هذه الشاشة فقط، اضغط **/** وابحث باسم الملف كاملًا أو جزئيًا أو بمساره النسبي؛ ستظهر نتيجة توضح وجود تطابق تام، كما ستعرض النتائج الجزئية ومساراتها وبصمات SHA-256. اترك البحث فارغًا لإظهار القائمة كاملة، ثم Enter أو Esc للعودة. أما **Update Task Report** فيحفظ ملخصًا نصيًا قصيرًا في سجل المهمة، ولا يرفق مستندًا.
7. أعطِ AI Agent اسم المهمة أو معرّفها، واطلب منه تنفيذ العمل على ملفات المشروع الأصلية. ضع فقط التعليمات والتسليمات والتقارير والبرامج النصية والأمثلة والمراجع المطلوبة داخل مجلدات دعم المهمة، وأبقِ ملفات المصدر في شجرة المشروع الأصلية.

للمستخدمين المتقدمين، تبقى أوامر Core CLI متاحة لإدارة المهام. لاستخدامها من PowerShell، حدّد مجلد تثبيت AIPM ومسار السجل ومعرّف المشروع المسجل:

إذا كانت الملفات التي تعمل عليها داخل مجلد فرعي لمهمة ضمن مشروع مسجّل، فلا تسجّل ذلك المجلد كمشروع. أنشئ سجل مهمة داخل المشروع باستخدام معرّف المشروع، واكتب مسار المجلد الموجود ضمن نطاق المهمة أو تعليماتها. تنشئ AIPM مجلد حالة خاصًا بالمهمة، بينما يواصل الوكيل العمل على الملفات الموجودة في مساراتها الأصلية. اختر عنوانًا وصفيًا؛ تنشئ AIPM معرّف `Task-ID` فريدًا، ولا يلزم استخدام أسماء مثل `Task 01`. سجّل المجلد كمشروع منفصل فقط إذا كان مساحة مشروع مستقلة فعلًا.

```powershell
$aipmRoot = 'D:\Path\To\AI-Project-Manager-AIPM'
$registry = Join-Path $env:LOCALAPPDATA 'AI-Project-Manager\registry.json'
$projectId = 'YOUR_PROJECT_ID'
$cli = Join-Path $aipmRoot 'Core-Engine\aipm.py'

$createdJson = python $cli task-create --registry $registry --project-id $projectId --title 'Add Search' --scope 'Add and verify search in the existing application.'
if ($LASTEXITCODE -ne 0) { throw 'تعذر إنشاء المهمة.' }
$created = $createdJson | ConvertFrom-Json
$taskId = $created.task.task_id
$taskId
```

احتفظ بمعرّف المهمة الذي ظهر. أضف خطة، ويمكنك استيراد ملف تعليمات أو مرجع تحتاجه المهمة. استورد فقط ملفات المساندة؛ لا تنشئ نسخ عمل من ملفات الشيفرة التي يجب تعديلها في مسارات المشروع الأصلية.

```powershell
python $cli task-plan --registry $registry --project-id $projectId --task-id $taskId --text 'افحص البحث الحالي، ثم نفّذ التعديل في ملفات المشروع الأصلية وشغّل اختباراته.'
python $cli task-artifact-write --registry $registry --project-id $projectId --task-id $taskId --relative-path 'Instructions/Task-Instructions.md' --from-file 'D:\Work\My-Project\Task-Instructions.md'
```

ينفّذ الوكيل التغييرات بنفسه في ملفات المشروع الأصلية. عند التوقف أو تسليم العمل، سجّل ما تحقق فعلًا وما بقي. المسارات في `--changed-file` مراجع للملفات الأصلية ولا ينسخها AIPM ولا يغيّرها:

```powershell
python $cli task-checkpoint --registry $registry --project-id $projectId --task-id $taskId `
  --last-verified-action 'تم تنفيذ نموذج البحث في ملفات src الأصلية.' `
  --next-action 'شغّل الاختبارات المركزة وافحص Git diff وأصلح أي إخفاق.' `
  --completed-work 'أضيف نموذج البحث وربط بالمعالج الموجود.' `
  --changed-file 'src/SearchForm.tsx' `
  --test-result 'UNVERIFIED: لم تُشغّل الاختبارات بعد.'
python $cli task-read --registry $registry --project-id $projectId --task-id $taskId
python $cli task-artifact-list --registry $registry --project-id $projectId --task-id $taskId
```

على الوكيل التالي فتح مجلد المشروع نفسه وقراءة `Task-State.md` و`Handoff/Next-Agent-Handoff.md` وأي تعليمات أو مراجع. بعد ذلك يفحص ملفات المصدر الحالية وGit diff ودليل الاختبارات قبل الاستكمال؛ فلا تعتبر الملاحظات القديمة إثباتًا أن الملفات لم تتغير. يسجل AIPM ما يبلغه الوكيل ولا يشغّل اختبارات المشروع ولا يفرض موافقة منه على تعديل ملفات المصدر.

تشمل الأوامر الأخرى `task-list` و`task-blocker-add` و`task-blocker-clear` و`task-verify` و`task-report` و`task-artifact-read`. ملفات المهمة محدودة بمجلدات مصنفة وبحجم أقصى 16 ميغابايت لكل ملف. لا يستبدل AIPM ملفًا موجودًا بصمت؛ عند تحديثه أرسل قيمة `--expected-sha256` الحالية.

## 11. افهم المهارات والمطالبات وAgent Bridge

يمكن لمالك المشروع إضافة المهارات أو حذفها من `01-Skills-General/`، وإضافة المطالبات المستقلة أو حذفها من `02-Prompt-General/`. قبل التعديل:

1. أنشئ نسخة احتياطية أو احفظ التغيير في Git حتى تستطيع مراجعته أو التراجع عنه.
2. استخدم اسم المجلد التقني وملف `SKILL.md` بوضوح.
3. راجع المصدر وشروط الرخصة؛ فرخصة المشروع لا تلغي حقوق مؤلفي الطرف الثالث.
4. اتبع SemVer: ابدأ المهارة الجديدة أو المعاد ضبطها بالإصدار `1.0.0`، ثم حدّث الإصدار عند تطويرها.
5. حدّث الإصدار وسجل التغيير قبل تحديث بيانات الفهرس المحمي.
6. تحقّق من الفهرس وأعد بناء عينة الجسر المحلية بالأوامر التالية.

```powershell
python Maintenance-Tools\Invoke-Capability-Library.py validate
python Maintenance-Tools\Invoke-Capability-Library.py refresh-baseline --confirm-integrity-baseline-update --reason "Describe the authorized catalog change"
python Maintenance-Tools\Invoke-Capability-Library.py build-plugin
python Maintenance-Tools\Invoke-Capability-Library.py validate-plugin --output Plugins\aipm-project-agent-bridge
```

لا تشغّل `refresh-baseline` إلا بعد اعتماد التغيير وتحديث الإصدار وسجل التغيير. لا تعدّل `Capability-Library/Registry.json` أو سجل المصدر يدويًا. اترك الجسر محليًا وغير منشور ما لم يوافق المالك بصورة مستقلة على تثبيته أو نشره في مضيف مدعوم.

## 12. استخدم وكيل ذكاء اصطناعي بأمان

فتح المشروع في محرر يعمل بالذكاء الاصطناعي لا يثبّت الجسر ولا يبدأ وكيلًا ولا يمنح صلاحيات للملفات تلقائيًا. لا يحصل الوكيل المتوافق إلا على صلاحيات المضيف التي منحها المالك صراحةً. اقرأ [عقد محول المضيف](../../Plugins/Adapters/Host-Adapter-Contract.md) قبل تفعيل أي تكامل.

عند استخدام AIPM لإدارة مشروع آخر، لا تفتح مجلد تثبيت AIPM نفسه كمساحة عمل قابلة للكتابة لذلك الوكيل. تمنع النواة عملياتها من الكتابة إلى مسار AIPM أو مسار يتداخل معه، كما تطلب قاعدة `AGENTS.md` ترك ملفات AIPM دون تغيير إلا إذا طلبت صراحةً تطوير AIPM أو إصلاحه. هذا ليس حاجزًا على مستوى Windows؛ فالوكيل الذي يملك صلاحية مباشرة لكتابة أي ملف يستطيع تجاوز النواة. استخدم إعدادات مساحة العمل أو العزل في المضيف أو Windows ACL لمنع الكتابة إلى مجلد AIPM.

عند نقل العمل إلى جلسة أخرى، تعامل مع الملخصات المنسوخة كسياق لا كدليل. يجب أن تعيد الجلسة المستلمة قراءة الحالة والأدلة الحالية للمشروع. وتظل أي معلومة لا تدعمها أدلة قابلة للتحقق **مجهولة** أو **غير متحقق منها**.

## 13. أنشئ ملف مصدر وتحقق منه

لإنشاء أرشيف مصدر قابل لإعادة الإنتاج داخل `Releases/`:

```powershell
python Maintenance-Tools\New-Release-Package.py build
python Maintenance-Tools\New-Release-Package.py verify --archive Releases\AI-Project-Manager-v1.0.2.zip
```

تضم الحزمة مواد المشروع المخصصة للنشر ودليلي المبتدئين، وتستبعد قاعدة بيانات Git والملفات المؤقتة ومساحات الاختبار وخطط التنفيذ الداخلية. يتحقق الأمر من المجموع الاختباري وسجل بصمات الملفات. نجاح البناء المحلي لا يعني إنشاء إصدار على GitHub أو تثبيت الحزمة أو تفعيلها في مضيف.

## 14. حلول لمشكلات شائعة

| المشكلة | الحل |
| --- | --- |
| الأمر `python` غير معروف | ثبّت Python 3.10 أو أحدث، وافتح PowerShell من جديد، ثم نفّذ `python --version`. |
| الواجهة ترفض البدء | شغّلها من طرفية تفاعلية، لا من خلال أنبوب أو جلسة معاد توجيه مدخلاتها. |
| PowerShell 7 غير متاح | استخدم `AIPM.bat` أو أمر Windows PowerShell 5.1 أعلاه. |
| تظهر `NOT_REGISTERED` | اختر **Registry Management** ثم سجّل مجلد المشروع المقصود. لن يضيف AIPM إلا مجلد الحالة بعد تأكيدك. |
| تسألك الواجهة عن مكان السجل | وافق على المسار تحت `%LOCALAPPDATA%\AI-Project-Manager` أو اكتب المسار الكامل لأي ملف خارج تثبيت AIPM؛ اختر اسم الملف والمجلد كما تريد، مع إنهاء اسم الملف بـ`.json`. لا يكفي إدخال مسار المجلد وحده. |
| تظهر `AIPM_PLATFORM_PROTECTED` | مسار المشروع أو السجل أو النسخة الاحتياطية يتداخل مع AIPM. اختر مشروعًا أو موقع تخزين منفصلًا؛ تمنع النواة هذا الإجراء عمدًا. |
| تظهر المهارة بحالة غير متحقق منها | اعتبرها دليلًا غير مكتمل، لا تثبيتًا ناجحًا. راجع المصدر والفهرس المحلي. |
| يظهر رمز بصورة غير صحيحة | اضبط `AIPM_ICONS=ascii` أو راجع إعدادات الثيم في دليل TUI. |

## 15. قائمة تحقق للجلسة الأولى

1. اقرأ الرخصة وملف README.
2. تحقق من إصداري Python وPowerShell.
3. افتح الواجهة، وافق على مكان السجل، واستكشف اللوحة.
4. شغّل `health` و`catalog` و`host-capabilities`.
5. اقرأ مصفوفة الدعم وسجّل أي عنصر حالته `UNVERIFIED`.
6. لا تثبّت الجسر ولا تمنح وكيلًا صلاحية جديدة ما لم يعتمد المالك هذا التكامل المحدد.
7. سجّل مجلد المشروع المقصود فقط. تحقق من أن المحتوى الذي أنشأه AIPM هو مجلد `Shared-Project-State-Manager/`؛ لن تتغير ملفات المصدر الموجودة.
